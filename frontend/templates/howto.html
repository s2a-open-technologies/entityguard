Anleitung

Was ist EntityGuard?

EntityGuard ist eine Datenschutz-Schutzschicht für LLM-gestützte Anwendungen. Bevor Texte an ein Sprachmodell gesendet werden, erkennt und anonymisiert EntityGuard sensible Daten (z. B. Patienten-IDs, Namen, Diagnosen) auf Basis von Microsoft Presidio und einem deutschen spaCy-Sprachmodell, um DSGVO- und HIPAA-Vorgaben einzuhalten. Über dieses Admin-Interface konfigurieren Sie, welche Datentypen erkannt und wie sie ersetzt werden.

Erkennungsquellen

Eine Entität kann aus drei Quellen Treffer bekommen. Die Liste Entitäten zeigt pro Entität, was sie tatsächlich erkennt — die Detailseite ebenso:

Muster

Von Ihnen gepflegte Regexe bzw. Stichwort-Listen (siehe unten). Erscheint als Chip „Muster“.

Standard-Engines

Eingebaute Erkennung: spaCy für Personen, Orte und Organisationen sowie Presidio für E-Mail und Telefon. Erscheint als Chip „spaCy“ bzw. „Presidio …“.

Modelle

Optional zugeschaltete KI-Modelle (siehe Modelle). Erscheint nur als Chip „Modell: …“, wenn das Modell gerade aktiv ist.

Hat eine Entität keine dieser Quellen, wird sie als ⚠ nicht erkannt markiert — ihre Treffer würden dann nie maskiert.

Grundbegriffe

Entität

Die zentrale Einheit: der Datentyp, der geschützt werden soll (z. B. PATIENT_ID). Jede Entität hat einen Platzhalter (z. B. [PATIENT_ID]), der die erkannten Werte im anonymisierten Text ersetzt.

Muster

Erkennt konkrete Textstellen für eine Entität - entweder als Stichwörter (einfach Begriffe eingeben, der Ausdruck wird automatisch gebaut) oder als Regex für Fortgeschrittene. Jedes Muster hat einen Score (0.0–1.0).

Kontextwörter

Begriffe, die in der Nähe eines Treffers die Erkennung wahrscheinlicher machen (z. B. "Patient", "Fall", "Akte"). Sie verbessern die Trefferquote, ohne selbst als Muster zu dienen.

Modelle

Optional zuschaltbare KI-Modelle (z. B. für Namen oder IBANs), die parallel zu den Mustern laufen. Sie werden unter Modelle einfach ein- oder ausgeschaltet.

Neue Erkennung einrichten

So legen Sie Schritt für Schritt eine neue Erkennung für einen sensiblen Datentyp an:

  1. Entität anlegen unter Entitäten → Entität erstellen. Vergeben Sie einen eindeutigen Namen und einen Platzhalter für die anonymisierte Ausgabe.
  2. Muster hinzufügen auf der Detailseite der Entität: entweder Stichwörter eingeben (einfach) oder eine Regex (fortgeschritten) - mit Score. Für häufige Fälle gibt es unter dem Formular Vorlagen (Telefon DE, IBAN, Datum, PLZ, E-Mail, Straße+PLZ Ort), die den Regex-Modus mit einem fertigen Ausdruck füllen.
  3. Kontextwörter ergänzen (optional), um die Trefferquote in echten Texten zu erhöhen.
  4. Muster testen mit dem Muster-Tester auf der Detailseite, bevor Sie live gehen. Klicken Sie dazu eine Musterzeile an, um sie direkt in den Tester zu übernehmen.
  5. Entität aktivieren (Status "Aktiv"), damit sie bei der Textverarbeitung berücksichtigt wird.
  6. Erkennungsquellen prüfen: Steht in der Spalte „Erkennung“ ein ⚠ nicht erkannt, fehlt ein Muster oder ein aktives Modell.

Tipps

  • Der Score gibt an, wie sicher ein Treffer ist: 1.0 bedeutet höchste Konfidenz, niedrigere Werte eignen sich für unscharfe oder mehrdeutige Muster.
  • Für einfache Begriffslisten (z. B. Krankenkassen) reicht der Stichwort-Modus - er baut automatisch ein Muster mit Wortgrenzen.
  • Für Experten: Regexe folgen der Python-re-Syntax. Testen Sie neue Muster immer zuerst mit dem Muster-Tester.
  • Die deutsche spaCy-Erkennung findet manche Namen nur isoliert; das Standard-Muster anrede_name fängt „Herr/Frau/Patient + Name“ auch im Fließtext. Für noch mehr Robustheit ein Modell unter Modelle zuschalten.
  • Inaktive Entitäten bleiben erhalten, werden aber bei der Textverarbeitung ignoriert – nützlich zum Vorbereiten oder vorübergehenden Deaktivieren.
